# Obsidian Markdown evaluation

Synthetic fixtures; no real vault or private task content. Copy fixtures into a disposable run directory. Supply the vault root explicitly where the case does so. Never use the machine's configured storage.

Cases test triggering as labels, not measured automatic routing. Positive cases cover knowledge and progress representation, existing schema/edit boundaries, unknown roots, stable property types, digit-leading tags, provider-owned events and mixed output constraints. Negative cases distinguish prose editing, retrieval and task history.

For behavior, freeze criteria before runs and pair the same prompt, fixtures, model and permissions with the candidate versus no format skill. For storage changes, compare against a pre-change skill snapshot, not an empty baseline. Inspect actual outputs, tool traces and resulting fixture state. Parse YAML with duplicate-key rejection and verify referenced files/headings under the correct base. A simulated MCP case tests reasoning only, not real interoperability.

Keep run outputs, upstream snapshots, grading and research outside published skill artifacts, under the active task workspace or a private temporary workspace. Report sample size, model, failed cases and limits; one paired run is not reliability evidence.
